COLLECTION — отдельный рабочий контур

Адрес: https://release.109.235.118.171.sslip.io/collection
Android: /downloads/Collection.apk и /downloads/Collection-Driver.apk

Изоляция
Отдельный Compose-проект collection-live, PostgreSQL collection_live, собственные
тома, Redis и случайные секреты JWT. Старый bioflow-test не обновляется и его БД
не используется. На общем входном Nginx добавляется только виртуальный хост
нового адреса. Перезапуск отладочного прокси восстанавливает отдельный маршрут
через reconciliation timer; сертификат обновляется отдельным timer.
Новые маршруты дополнительно требуют COLLECTION_ENABLED=true и collection_*
в имени БД. В production требуется точное имя collection_live.
Пользовательские учётные записи bootstrap не создаёт.

Роли
OWNER: все объекты, отправки, водители, сборщики, остатки, движение, уведомления.
COLLECTOR: создание отправки сырья и QR, собственные рейсы и уведомления.
WAREHOUSE_MANAGER: только назначенные склады, приёмка, мойка, отправка на завод.
FACTORY_MANAGER: только назначенные заводы, приёмка мытого, выпуск ГП/некондиции,
отправка выбранных бигбегов ГП по QR.
Водитель: отдельное приложение без регистрации, QR, госномер и телефон,
«Загрузился», «Выехал», «Прибыл». Телефон не подтверждается по SMS.
Назначения хранятся в CollectionMembership. Пользователей добавляют отдельно
после получения их данных от владельца, без демонстрационных аккаунтов в live.

Учёт
Начальные четыре склада создаются bootstrap. Частные начальные остатки читаются
из /run/collection-secrets/opening-balances.json и не хранятся в публичном коде.
opening-collection.ts проверяет точность и источник, повторно не добавляет остатки
и не сбрасывает remainingKg после операций. Несовпадение исходной суммы требует
отдельной проверенной корректировки, а не перезаписи истории.
Внутренняя единица: кг, Decimal(18,3); интерфейс показывает также тонны.
Сырьё после «Прибыл» создаёт ожидающий приход. До подтверждения оно недоступно.
Мойка переводит заданный вес из немытого в мытое без изменения общей массы.
Отправка мытого списывает доступный остаток склада; завод зачисляет его только
после подтверждения. Средний вес бигбега вычисляется по общему весу и количеству.
Выпуск завода списывает из мытого сумму веса всех бигбегов ГП и некондиции.
Вес каждого бигбега сохраняется отдельно. Для доставки ГП выбирают доступные
бигбеги: их количество и вес вычисляются, повторная отправка исключена.
Прибытие ГП отмечает доставку; в немытое сырьё такая доставка не попадает.
Списание FIFO, операции блокируют строку объекта в транзакции и проверяют остаток.
Идемпотентность привязана к организации, пользователю, ключу и содержимому запроса.

Уведомления
Владелец/администратор организации включается в каждое уведомление учётного
события. Объектовые ответственные и создатель рейса получают свои события.
Покрыты QR/отправка, подключение водителя, загрузка, выезд, прибытие, подтверждение,
мойка, отправка и приёмка завода, выпуск, доставка ГП, остановка и потеря координат.
Уведомления создаются в той же транзакции, что и движение: откат не уведомляет.
CollectionNoticeLink связывает запись с конкретным рейсом, приходом или объектом.
Веб открывает нужный раздел и карточку, немедленно обновляя её данные.
FCM передаёт section/entity/recipient. Android/iOS обрабатывают нажатия из фона,
холодного запуска и кнопку «Открыть» при открытом приложении. Сервер повторно
проверяет права на подтверждение независимо от данных уведомления.
При смене пользователя push-токен снимается со старой записи устройства.
Выход со всех устройств отзывает сессии и регистрацию push.
Транзитные ошибки FCM повторяются без ограничения в десять попыток, с задержкой;
все уведомления при этом сохраняются во внутреннем кабинете.
Веб-остатки обновляются каждые 5 секунд, уведомления — каждые 15 секунд.

Геолокация
Android: native foreground service с видимым уведомлением и остановкой.
iOS: CoreLocation, режим background location, индикатор, «Всегда», outbox и
фоновая URLSession. Проекты и схемы driver/collection подготовлены для Xcode.
Данные сначала сохраняются локально. Повторы отправки не дублируют координаты.
Этапы рейса также сохраняются и отправляются по порядку после подключения.
После «Прибыл» сбор останавливается; остаток очереди досылается в фоне.
Для первоначальной проверки QR и привязки рейса требуется интернет.
Сессия сбора: максимум 24 часа, поздняя загрузка записанных данных — ещё 7 дней.
Отсутствие новых координат 10 минут вызывает одно предупреждение за перерыв;
свежая координата закрывает перерыв. Сервер не отличает отсутствие GPS от
отсутствия интернета или остановки приложения и сообщает это прямо.
Принудительное завершение/перезапуск телефона и ограничения производителя могут
остановить трекер: после них приложение нужно открыть и проверить статус.

Сборка
apps/mobile/build-collection-mobile.sh collection android debug
apps/mobile/build-collection-mobile.sh driver android debug
apps/mobile/build-collection-mobile.sh collection ios release
apps/mobile/build-collection-mobile.sh driver ios release
FIREBASE_CONFIG_FILE задаёт соответствующий публичный google-services.json или
GoogleService-Info.plist. API_URL и WEB_URL по умолчанию используют новый адрес.
Для Android release нужен ключ владельца в ignored android/key.properties.
Для iOS нужен macOS/Xcode и подпись Apple Developer; APNs подключается на этапе
публикации по решению владельца. Android-файлы собираются в release и подписываются отдельным ключом проекта.
Ключ и пароль сохраняются только в закрытом shared/secrets сервера; они не
монтируются в API/web-контейнеры и не входят в репозиторий или APK.

Секреты и развёртывание
Репозиторий публичный. Частные ключи и реальные начальные остатки не коммитятся,
не входят в APK, Docker build context или исходный git archive.
Firebase проверен OAuth и validate_only, без сообщения на реальный телефон.
Конфигурация и начальные остатки передаются AGE-конвертом для проверенного
SSH host key сервера, расшифровываются только на сервере в shared/secrets (0600).
Публикуются только приложения; публичный release содержит части сжатого APK
архива и контрольные суммы. APK для сервера собираются и подписываются в Actions
из проверенного CI commit; временная конфигурация подписи удаляется после сборки.
Ручной deploy-production запускается с contour=collection из feature ref после
успешного CI точного commit. Legacy job при таком запуске пропускается.
Перед обновлением резервируется только новая база; автоматического восстановления
БД поверх пользовательских изменений нет. При ошибке нового proxy route
восстанавливается только прежняя конфигурация прокси.

Проверки
55 серверных unit tests; HTTP/PostgreSQL полный цикл всех ролей на отдельной
collection_*_spec, включая параллельные списания, доступ чужих объектов, повторы,
уведомления владельца/объектов и регистрацию push при смене пользователя.
Playwright: четыре роли, QR/PNG, открытие прихода из уведомления, приёмка,
мойка, завод, выпуск ГП/некондиции, доставка ГП, мобильная ширина без overflow.
Flutter analyze и 18 тестов; Android APK package/label проверены.
iOS plist/scheme/project structure проверена; сборка и фоновые сценарии на
физическом iPhone не проверены в Linux. APNs и App Store подпись отложены.
Реальная доставка FCM и длительный GPS на телефоне требуют установки и регистрации
устройства после создания пользователей. Наличие кода/очереди не заменяет этот тест.
