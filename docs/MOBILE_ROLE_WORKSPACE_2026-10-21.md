# Полный кабинет роли в Android

После входа приложение показывает русские названия ролей пользователя и меню доступных ему разделов. Меню учитывает совокупность разрешений и доступ к объектам из `/auth/me`; название роли само по себе не даёт прав. Встроенный полный кабинет использует тот же интерфейс и API, что Web: пользователи, стандартные роли и назначения объектов, справочники, настройки, сессии, аудит, все операции и отчёты доступны по тем же правилам.

## Пользователю

Откройте меню слева от заголовка — «Разделы моей роли». Выберите раздел: кабинет откроется внутри приложения без повторного пароля. Внутри кабинета меню справа позволяет переходить между разрешёнными разделами. Имя и русские названия ролей остаются в заголовке.

Сохранение CSV/XLSX/PDF и вложений открывает системный выбор места сохранения Android. Загрузка фото/PDF через полный кабинет использует системный выбор документов. «Печать QR» открывает службу печати Android; в документе только QR на белом фоне. Эта кнопка доступна также в подтверждении сохранения на быстрых нативных экранах.

Быстрые вкладки добычи, рейсов, остатков, операций и уведомлений сохранены. Вкладки и действия без соответствующих прав скрыты. Их прежняя офлайн-очередь остаётся разделённой по пользователям. Полный кабинет, как Web, требует подключения. На возврате назад сохраняется предупреждение о несохранённой форме.

Для смены прав/назначений администратор использует «Пользователи» и «Партии и операции» → «Доступ». При следующем открытии кабинета профиль обновляется с сервера. Новым пользователям перед началом работы требуется сменить временный пароль.

## Сессии и файлы

`POST /auth/mobile-web-session` защищён обычным JWT guard; нельзя задать другого пользователя/организацию телом запроса. Guard блокирует заблокированных пользователей, отозванные сессии и обход обязательной смены пароля. Выдаётся отдельная сессия того же пользователя, поэтому обновление Web refresh token не меняет нативную сессию. Права и области доступа проверяются сервером при каждом запросе.

Секреты передаются только в память документа через канал приложения; не помещаются в URL, cookies или localStorage. Переход WebView на посторонний origin/путь блокируется. При закрытии известная дочерняя сессия отзывается и память кабинета очищается; при выходе очищается также нативный вход. Смена аккаунта проверяется до обработки сообщений. Новые таблицы/миграции не нужны.

Файлы сохраняются через Android Storage Access Framework с выбором пользователя, без широкого доступа к файловой системе. Размер файла полного кабинета ограничен 20 МБ; обычный Web этим ограничением не затронут. Печать принимает только ограниченное по размеру квадратное PNG и строит одну страницу с QR размером до 50 мм. Произвольный HTML/страница в службу печати не передаётся.

## Проверка

- Flutter: анализ, существующие проверки разделения сессий/очередей, новые проверки меню по реальным разрешениям и русских названий.
- HTTP acceptance на отдельной `*_spec` базе: SSO для текущего actor, отсутствие авторизации, обязательная смена пароля, отдельное обновление refresh, отзыв дочерней сессии, сохранность нативного refresh и ограничения складского пользователя.
- Browser UAT на настоящем API/PostgreSQL: вход без повторного пароля, меню администратора, отказ административного доступа аудитору, отсутствие секретов в URL/localStorage, сохранность родительской сессии. В этой проверке моделируется только транспорт JavaScript-канала, не API/данные; настоящий Android-канал проверяется отдельно.
- Расширенный Android UI workflow использует настоящий Next/API и одноразовую базу. Проверяет 11 ролей, кабинет внутри WebView, создание пользователя/назначение русских ролей, новый многоролевой вход со сменой пароля, системное сохранение CSV и печать QR через системную службу в PDF. ADB-снимки показывают сам Android, включая платформенный WebView. Контроллер выбора/печати доступен только локальному одноразовому эмулятору CI и не включён в приложение.

Результаты конкретного CI/run и артефакты фиксируются в отчёте завершённого запуска. Эмулятор/PDF не заменяют проверку физической камеры и принтера. Изменения схемы БД и перенос рабочих данных не требуются.

## Обновление тестовой APK

Тестовая версия — 0.2.0+2. Для последующих сборок deployment сохраняет один тестовый ключ подписи в приватном каталоге сервера (0700/0600); ключ не входит в Git, публичные загрузки или артефакты CI. Это не выпускной ключ владельца. Предыдущие APK могли использовать другой временный debug-ключ. Перед первым обновлением отправьте команды из старой офлайн-очереди. Если Android сообщает конфликт подписей, сначала убедитесь, что очередь отправлена; только затем переустанавливайте приложение и входите тем же аккаунтом. Серверные документы от переустановки не удаляются; неотправленная локальная очередь может быть потеряна. Автоматическое удаление старого приложения не выполняется.
