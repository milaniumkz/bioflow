Перед изменениями Codex должен прочитать инструкции репозитория, проверить текущие изменения и существующую реализацию: `apps/web/app/page.tsx`, `apps/web/app/ledger.tsx`, `apps/mobile/lib/main.dart`, `apps/mobile/lib/role_access.dart`, `apps/backend/prisma/roles.ts`, серверные обработчики, схемы, тесты и миграции. ## Полнота и смысл статусов

157 представлений: 104 mobile и 53 web. Все 59 семейств аудита покрыты; ещё 8 кадров показывают общие состояния. В `SCREEN_MANIFEST.json` каждому представлению сопоставлены PNG, HTML, исходный JS, семейство, роли, компоненты и семантические действия.

- `current` — семейство существовало в проверенном снимке; дизайн не доказывает работу каждой нарисованной кнопки.
- `rework` — переработка существующего сценария с новыми элементами; отдельно сверить недостающую функциональность.
- `requested` — запрошенный сценарий, не подтверждённый в снимке: не называть готовым.

В манифесте 99 current, 39 rework и 19 requested. Ключи M/W/S — идентификаторы дизайна, не маршруты приложения. Ключ навигации не является URL. Фактические URL и API-контракты инвентарём не зафиксированы, поэтому `path`, `route_path`, `endpoint`, `method` остаются null, а backend `verified` — false. Семантические имена действий обозначают намерение интеграции, их нельзя автоматически превращать в endpoint. `verified:true` у navigation key подтверждает только наличие ключа в аудите, не точное связывание нового кадра с существующей страницей.

## Проверенные роли и область

Роли ниже сохраняются точно, без переименования технических кодов. Точная проверенная permission-модель сохранена в `roles_verified` манифеста; не заменять её обобщённой фразой «все действия на экране».

| Технический код | Название | Проверенная область |
|---|---|---|
| `OWNER` | Владелец | `all` |
| `ADMIN` | Администратор | `administration` |
| `CONTRACTOR_REP` | Представитель подрядчика | `own_organization` |
| `RECEIVER` | Приёмщик | `assigned_objects` |
| `WASH_OPERATOR` | Оператор мойки | `assigned_objects` |
| `PRODUCTION_OPERATOR` | Оператор производства / завода | `assigned_objects` |
| `DISPATCHER` | Диспетчер | `assigned_objects` |
| `EXTRACTION_OPERATOR` | Оператор добычи | `assigned_objects` |
| `LOADING_OPERATOR` | Оператор погрузки | `assigned_objects` |
| `WAREHOUSE_OPERATOR` | Оператор склада | `assigned_objects` |
| `AUDITOR` | Наблюдатель/аудитор | `read_only` |

Права нескольких ролей объединяются, затем применяются реальные объектные ограничения на сервере. AUDITOR — только чтение. CONTRACTOR_REP — своя организация. Назначение на экран в дизайне не разрешает все мутации этого экрана. Значение `all` означает общую оболочку/экран с фильтрацией по фактическим правам, а не неограниченный доступ. Несоответствие UI текущему серверному разрешению решать в пользу защиты данных, не расширением прав.

## Запрошенные роли, не backend-коды

- `COLLECTOR_REQUESTED` — Сборщик; реальный backend `code: null`.
- `DRIVER_REQUESTED` — Водитель; реальный backend `code: null`.
- `LAB_REQUESTED` — Лаборант; реальный backend `code: null`.
- `PACKER_REQUESTED` — Упаковщик; реальный backend `code: null`.

Эти четыре ключа нужны для точной связи дизайна с требованием. Не создавать их как enum, permission или миграцию автоматически. Сначала найти возможную более новую реализацию; если её нет, явно спроектировать минимальные разрешения и область объектов. Нельзя молча отождествлять сборщика с EXTRACTION_OPERATOR либо упаковщика с WAREHOUSE_OPERATOR.

## Границы внедрения

- Авторизация и объектная область — серверные проверки, не только скрытие кнопок.
- GPS, лаборатория, индивидуальные QR, упаковка и новый сценарий первой отправки требуют проверки текущих данных и миграций. Дизайн сам по себе не подтверждает их наличие.
- «Продажа» здесь означает количественный отпуск материала, включая мытый материал. Оплаты, цены, финансовые остатки, кошелёк и платёжные интеграции не входят в объём.
- Исходный QR связывает историю партии; QR каждой единицы связан с исходной партией. Подтверждения не должны давать повторный приход/расход.
- Пакет подготавливает внедрение, но не означает, что код уже изменён, задеплоен или протестирован на устройствах.
