## Реализовано

Партийный учёт добычи и распределение на рейсы; фото, QR, брутто/тара/нетто и грузоподъёмность; приёмка частями и с расхождениями; отдельная разгрузка и завершение; точные остатки/резервы; перемещение, производство из нескольких партий с материальным балансом, отгрузка, возврат, корректировка и инвентаризация. Прослеживаемость до исходной партии, подрядчика и места добычи. Аудит и движения защищены от перезаписи, отмены создают обратные движения. Повтор команды не повторяет списание; конкурентные операции проверяются транзакционно.

Объектные права, актуальные серверные роли, отзыв сессий, смена временного пароля, архивирование справочников, защищённые файлы. Веб и Android подключены к партийным API; мобильная очередь привязана к пользователю и сохраняет ключи идемпотентности. Отчёты CSV/XLSX/PDF, внутренние уведомления и очередь FCM. Карты и геолокация не добавлялись.

## Проверено исполнением

- 42 теста backend, 1 тест API-клиента; команды type-check проходят. Веб-команда test содержит 0 тестов и не считается подтверждением интерфейса.
- Приёмочные AT01–13 и дополнительные проверки конкурентного списания, возвратов, объектных ограничений и выгрузки более 500 строк: 17 успешных проверок, включая родительский сценарий. Использованы PostgreSQL, Redis и настоящее приватное S3; повторено через Docker API.
- Сборка Docker API и веб; health API с БД и Redis.
- Браузер: вход, создание партии через реальные справочники, переход к остаткам и отчётам. Это выборочная проверка, не полный UI-регресс.
- Flutter: анализ без замечаний и 4 теста очереди/конфликтов/идемпотентности/формы входа. Debug APK собирается с тестовым адресом Android-эмулятора.
- Проверка невалидного JWT (401), ограничения временного пароля (403), успешной смены и немедленного отзыва прежней сессии на свежей сборке API.
- Создание и восстановление PostgreSQL backup в отдельную пустую тестовую БД.
