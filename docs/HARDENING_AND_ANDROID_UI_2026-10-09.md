## Безопасные серверные операции

GitHub Actions → `server-readiness` → Run workflow → ветка `main`:

1. `inspect`: читает текущий commit, DNS, состояние контейнеров, расписание backup и свободное место; бизнес-данные не изменяет.
2. `verify-backup`: проверяет SHA256 последней парной копии БД/файлов, восстанавливает отдельную временную БД и отдельный файловый том, проверяет FK, миграции, наличие файлов, размеры и контрольные суммы. Удаляет только собственные временные ресурсы. Рабочая база не восстанавливается поверх текущей.
3. `enable-https`: сначала проверяет, что DNS `bio.app.kz` указывает строго на `109.235.118.171`. При отсутствии записи завершается до изменения конфигурации. После настройки DNS выдаёт сертификат, проверяет HTTPS и устанавливает автоматическое продление. Доступ по IP HTTP сохраняется для тестового APK.

Повторный тестовый деплой: `server-ops` → `launch-test` на проверенном `main`. Он сохраняет рабочие данные и существующий HTTPS override. Операции `status/logs/restart` этого старого workflow относятся к другому production-пути; для диагностики тестового запуска используйте `server-readiness/inspect`.
