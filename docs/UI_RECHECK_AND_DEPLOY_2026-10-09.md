# BIOFLOW: повторное пользовательское тестирование и деплой, 09.10.2026

Проверено через реальный интерфейс Chromium с вводом в формы, кликами, загрузкой PNG в приватное S3, отказом от перехода с черновиком, переходами браузера назад/вперёд, потерей сети, перезагрузкой и повторным входом. Это браузерные сценарии, управляемые Playwright, с дополнительным визуальным просмотром скриншотов; не проверки кода вместо интерфейса.

## Результаты

- 23/23 повторных проверок исправленных дефектов успешны.
- 24/24 дополнительных проверок бизнес-цикла и нового пользователя успешны.
- Дополнительно подтверждены отсутствие служебного QR-хеша в карточке отчёта и сохранение именно новой партии (5 т) и двух новых PNG после перезагрузки.
- Итого 49 локальных UI-проверок и 221 проверка открытия экранов по 11 ролям. Ролевой обход не обнаружил HTTP/JavaScript-ошибок.
- Отдельная публичная проверка обновлённого сервера: форма входа открывается, нет JavaScript-ошибок, API/БД/Redis доступны. Вход и бизнес-действия на рабочих данных не выполнялись.

## Границы проверки

- Все бизнес-изменения выполнены только в изолированной копии PostgreSQL `bioflow_uat` и локальных Redis/S3, API 4140/Web 3040. Рабочие данные сервера не использовались для тестовых заказов, пользователей или загрузок.
- 221 проверка — открытие экранов по ролям, а не полная матрица всех ролей × действий × объектных назначений. Все 150 сценариев первоначального аудита по отдельности не повторялись. Исходный аудит и ТЗ сохранены.
- Android UI не проверен: `adb devices` пуст, устройство/эмулятор отсутствует. Успешная APK-сборка не означает успешное тестирование Android.
- Не подтверждены камера/галерея/QR на телефоне, доставка Firebase push, мобильный Web и другие браузеры, полное визуальное соответствие 13 Figma-экранам, нагрузка, восстановление серверной резервной копии.
- HTTPS `bio.app.kz` не подтверждён: проверка из облачной среды получила отказ CONNECT 403 прокси. Публикуется доступный HTTP-адрес тестового контура. Две moderate-записи Swagger/js-yaml из предыдущего аудита остаются; высоких/критических нет.

## Диагностика стенда и проверочных сценариев

При первых попытках полного цикла локальный SeaweedFS прекратил запись из-за недостатка свободного места. Удалены только восстанавливаемые кеши npm/Gradle, перезапущен исключительно S3 изолированного стенда с сохранением данных. После этого настоящая загрузка и повторное открытие PNG прошли. Сервер этим исправлением стенда не затронут.

Первые попытки скрипта также требовали уточнения селекторов: изменяемые подписи полей, два поля пароля на странице входа и отсутствие Обзора у нового аудитора с ограничением объектов. После исправления ожиданий итоговые 24 проверки прошли. Первичные журналы сохранены как диагностика, а итоговые подтверждения — `business-verified.log` (бизнес-цикл), `user-journey-final.log`, `report-check.log`, `persistence.log` и JSON со статусами.

Широкий ролевой обход и 23 регресса выполнялись до последнего изменения скрытия двух служебных полей. Новая production-сборка с этим изменением отдельно прошла бизнес-цикл, сценарии нового пользователя и целевую проверку карточки отчёта. Финальный CI проверил именно исходники, опубликованные в main.
