# Функциональная проверка Collection — 10 ноября 2026

Проверка выполняется на отдельной PostgreSQL `bioflow_spec`, Redis и приватном S3. Браузер работает с настоящим API: ответы бизнес-маршрутов не подменяются. Рабочая база, файлы и учётные записи предприятия не используются. Изменения схемы БД не требуются, APK не собирается.

## Матрица ролей и экранов

Проверяются все 19 штатных ролей: владелец, администратор, сборщик, водитель, приёмщик мойки, лаборант, оператор мойки, оператор завода, кладовщик готовой продукции, упаковщик, кладовщик продаж, представитель подрядчика, приёмщик, оператор производства, диспетчер, оператор добычи, погрузчик, кладовщик, аудитор.

`apps/web/scripts/check-role-workspace.cjs` входит через форму каждой роли и нажимает все доступные пункты меню, вкладки учёта, раскрывающиеся формы, открытие/закрытие карточек и обновление. Собирается перечень видимых кнопок, полей, вариантов выбора, обязательности и блокировок. Проверяются ошибки JavaScript, ошибочные ответы API и выход содержимого за ширину экрана. Раздельно используются размеры 1440 × 1000 и 390 × 1000.

Для пользователей производства проверяется отсутствие складских команд в выборе операций, для кладовщика — отсутствие производственных команд. Роли имеют полные **тестовые** назначения объектов, чтобы проверить наполненные экраны. Отсутствие назначений, чужая организация, чужой водитель и чужой склад отдельно проверяются серверными приёмочными тестами.

## Полный физический цикл через интерфейс

`check-physical-api-flow.cjs` проходит форму отправки сборщика: обязательные поля, шаги вперёд/назад, подтверждение, получение QR и чистый следующий черновик. Водитель сканирует QR и нажимает «Загрузился», «Выехал», «Прибыл». Затем отдельные роли выполняют приёмку с фото, анализ, подготовку к мойке, выпуск двух биг-бэгов, приём на завод, выпуск готового, приёмку склада, упаковку сканированием и продажу. Владелец планирует, отправляет и подтверждает доставку. Проверяется, что доставка не списывает склад повторно, а повторная упаковка не меняет исполнителя и не увеличивает счётчик.

Виртуальная камера передаёт настоящие изображения QR реального тестового API. Геолокация задаётся средствами браузерного теста. Бизнес-запросы, сохранение и история обрабатываются настоящим сервером.

## Складские операции через интерфейс

`check-ledger-operations.cjs` проверяет все десять видов общего учёта: перемещение, резерв, снятие резерва, списание, корректировку, инвентаризацию, мойку, производство, отгрузку и возврат. Проверяются черновик, подтверждение, допустимые отмены и итоговый материальный баланс. Исходный остаток для этого сценария создаётся штатными API партии, перевозки, взвешивания, приёмки и разгрузки, а не прямой записью остатков в БД.

Подтверждённый возврат остаётся неизменяемым и исправляется корректировкой. Его черновик можно отменить без изменения остатков. Отгрузка предлагает готовую продукцию; производство — мытое; мойка — сырьё. Для физических QR-партий общий учёт не обходит отдельные этапы.

## Исправления

- Поиск шрифта PDF учитывает фактический каталог Alpine `/usr/share/fonts/dejavu`; ошибки потока обрабатываются. CI создаёт русский PDF в собранном контейнере.
- Выгрузки используют обновление сессии, защиту от смены аккаунта и проверку формата файла, как обычные запросы.
- Ограничение запросов учитывает проверенного пользователя и шаблон маршрута. Разные сотрудники и разные справочники не расходуют общий лимит. Анонимный вход остаётся ограничен по адресу; смена ID и параметров запроса не обходит лимит маршрута.
- Повтор сериализуемой транзакции имеет короткую задержку, чтобы конкурирующие операции не повторялись одновременно без паузы.
- Справочники переиспользуются при переходах и обновляются после изменений. Новые операции не предлагают архивные объекты.
- В возврате используется выбор подтверждённой отгрузки, а не ввод внутреннего ID.
- Виды операций и управляющие кнопки соответствуют правам; входные партии — допустимому этапу. Поля входных партий очищаются после сохранения.
- Повторное использование того же файла запускает новую загрузку.
- Подтверждение пароля пересчитывает проверку при изменении обоих полей.
- Имена отчётов и счётчики документов показываются по-русски; защитный QR-токен не выводится в диалоге сохранения.

## Повторный запуск

Нужны Node 24, зависимости проекта, Chromium, Playwright и отдельные локальные PostgreSQL/Redis/S3. Запрещено направлять эти сценарии на рабочие данные.

1. На `localhost` подготовить `*_spec` БД, применить миграции и тестовый seed.
2. Выполнить `COLLECTION_INTEGRATION=1 COLLECTION_FIXTURE_FILE=/tmp/collection-fixture.json npm run test:collection -w @bioflow/backend` с тестовым `DATABASE_URL`.
3. Выполнить `NODE_ENV=test UI_FIXTURE_ORGANIZATION_ID=<orgId из fixture> npx tsx apps/backend/test/ui-fixture.ts` с той же БД. Это подключает 19 тестовых сотрудников к наполненной организации.
4. Запустить API с тестовыми DB/Redis/S3, `WEB_ORIGIN=http://localhost:3015`, `PORT=4102`; инициализировать S3 с тем же `WEB_ORIGIN`.
5. Собрать web с `NEXT_PUBLIC_API_URL=http://localhost:4102/api/v1` и запустить на 3015.
6. Запускать сценарии из корня репозитория. Для Playwright вне зависимостей проекта задать `PLAYWRIGHT_MODULE`; по умолчанию используется `require('playwright')`.

```bash
node apps/web/scripts/check-workspace-actions.cjs
node apps/web/scripts/check-physical-api-flow.cjs
node apps/web/scripts/check-ledger-operations.cjs
node apps/web/scripts/check-filter-fields.cjs
BIOFLOW_AUDIT_DIR=/tmp/role-desktop node apps/web/scripts/check-role-workspace.cjs
BIOFLOW_MOBILE=1 BIOFLOW_SKIP_EXPORTS=1 BIOFLOW_AUDIT_DIR=/tmp/role-mobile node apps/web/scripts/check-role-workspace.cjs
```

JSON-инвентаризация и снимки сохраняются в указанном временном каталоге. `BIOFLOW_AUDIT_ROLE` позволяет повторить одну роль; `BIOFLOW_AUDIT_DELAY_MS` задаёт паузу между разделами. Скачивания выполняются с паузой, поскольку браузер ограничивает слишком частые автоматические загрузки. Для одновременного прохода с разных размеров экрана можно использовать обратный порядок ролей через `BIOFLOW_AUDIT_REVERSE=1`.

Реальный смартфон, системный диалог сохранения, внешняя push-доставка, фоновый GPS при заблокированном телефоне и физический Bluetooth-принтер не заменяются браузерной эмуляцией. Подтверждение аппаратной работы требует отдельного прогона на устройстве; APK в рамках этой проверки не собирается.
