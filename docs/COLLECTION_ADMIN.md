# Администрирование Collection

Отдельный кабинет: `/collection/admin`. Вход по телефону и паролю существующего владельца или администратора. Публичная регистрация этих ролей закрыта. Используется только рабочая база Collection, без обращения к прежнему контуру.

## Управление

- Пользователи: создание, ФИО и телефон, роль, один или несколько объектов, блокировка / восстановление доступа, установка пароля без обязательной смены. Изменение роли и пароля отзывает сеансы. Последний владелец и собственный административный доступ защищены от случайного отключения.
- Объекты: создание, переименование, архивирование и восстановление складов / моек и заводов. Активные объекты автоматически доступны в самостоятельной регистрации.
- Материалы: фактический остаток немытого / мытого, отдельные корректировки бигбегов, списание и восстановление доступного бигбега. Все поля веса в тоннах; база и API сохраняют кг.
- Рейсы: отправки сырья и ГП, QR для скачивания и печати, карта, реквизиты и контакты водителя, исправление веса сырья, этапы, приёмка, отмена и отзыв доступа к GPS-сеансу.
- Производство: мойка, отправка на завод и подтверждение прихода, выпуск ГП / некондиции, обратная операция с восстановлением исходных партий.
- Уведомления: просмотр по всем получателям, состояние push, повторная доставка ошибок и сообщения пользователю / объекту / роли / всем.
- Журнал: страницы всех административных изменений с причиной и данными до / после. История движения также имеет пагинацию. JSON-выгрузка включает все операции, не только последнюю страницу.
- Настройки: открытие и закрытие самостоятельной регистрации; создание пользователей администратором остаётся доступным.

## Вход в веб-версию

После обновления нужно один раз войти заново. Затем вход сотрудников и админки сохраняется при обновлении страницы и повторном открытии сайта до 30 дней. Секрет сеанса находится в HttpOnly / Secure / SameSite Strict cookie, токены не записываются в localStorage. Параллельные вкладки восстанавливаются без ротационной гонки. Выход, блокировка, смена пароля или роли отзывают доступ; приложение водителя использует отдельный QR-сеанс.

## Сохранность данных

Каждый административный запрос проходит проверку роли и организации. Изменения материала блокируют соответствующие объекты и сохраняются с причиной, записью аудита и уведомлениями. Коррекция остатка использует ожидаемое значение: параллельное изменение приводит к конфликту, а не перезаписи.

Отмена не удаляет историю. Сначала отменяются последующие операции: доставка ГП → производство → приход на завод → мойка. Если результат уже использован, сервер останавливает отмену до возврата связанных партий. Начальные поступления сохраняются; корректировки отражаются отдельными действиями. Отзыв GPS-сеанса прекращает доступ по его токену, уже записанный маршрут сохраняется.

Пароли, хеши паролей, ключи Firebase, bearer-токены, push-токены устройств и QR-секреты не возвращаются в административной сводке или выгрузке. Журнал аудита остаётся неизменяемым.

## Проверка

`npm run test:collection -w @bioflow/backend` проверяет все роли, межорганизационные запреты, жизненный цикл аккаунта, отзыв сеансов, точные корректировки, идемпотентность, полную цепочку отмен и выгрузку без секретов в изолированной `collection_*_spec` базе. Дополнительно через настоящий браузер проверены операции из интерфейса, мобильная вёрстка, QR-скачивание, журнал, JSON-выгрузка и отказ сборщику. Производственная проверка выполняется без создания тестовых движений в рабочей базе.

## Начальные остатки завода

Ответственный завода в разделе «Остатки» однократно вводит мытое сырьё в тоннах, бигбеги готовой продукции (800 / 825 кг) и некондицию с весом каждого бигбега. Остатки добавляются отдельными партиями OPENING, не списывая сырьё и не заменяя уже учтённые приходы. Можно подтвердить нулевые позиции. Все позиции сохраняются одной транзакцией; блокировка объекта и постоянный маркер запрещают повторный ввод другим сотрудником, после повторного входа или смены устройства. Повтор сетевого запроса с тем же ключом безопасен. Владелец и ответственные получают уведомление, событие отражается в журнале и аудите. Последующие исправления выполняет владелец через админку с указанием причины.
